## 二、分层技术栈与选型理由

### 转写层
| 技术 | 为什么选它 | 量化收益 / 代价 |
|---|---|---|
| **Qwen3-VL-2B-Instruct**（VLM） | 简谱是"数字 + 点 + 线"的**结构化视觉布局**，端到端 VLM 比"检测框 + 分类"链路短、对版式变化鲁棒 | 2B 模型在本地 4070（8 GB）可跑；`JP_DTYPE=float16` 能兼容 P100/T4 |
| **贪心解码 + `output_scores=True`** | 要的不是"更花的解码"，而是**每个数字的可信度** | 置信度**零额外耗时**（实测开/关 30.1/30.0 s vs 30.0/30.4 s） |
| 多页拼接（`JP_MULTIPAGE`） | 一份谱常是 2–4 张竖图；只转第一页会得到"残谱" | 回锅 858 个目录：新稿 761 份、**487 份变长**（中位 **+276 音**，累计 **+184,274 音**） |
| 质量门（纯度 + 织体） | 站点里混着五线谱/和弦谱/钢琴织体，混进语料就是噪声源 | 三类判据各自可关；实测钢琴批 **24 份**被判织体跳过、0 份误杀 |

### 语料与数据层
| 技术 | 为什么 | 收益 |
|---|---|---|
| **纯文本曲谱 + JSONL 索引** | 人要能读、`git diff` 要能看、下游要零依赖 | 没有数据库/二进制格式；换台电脑只要有 Python 就能跑 |
| **自有 token 口径 `jptok.py`**（唯一真源） | 时值/变音/八度的写法极易各写一套、互相漂 | Python 与 JS 两份实现**逐 token 互锁**（21,711 token 比对一致） |
| **git 作为版本与回滚机制** | 语料改动要可追溯、可回滚、可审计 | 投稿写入即 `commit`（"反馈即入库"），`feedback/` 原文留档 |
| 幂等导入（只拷不覆盖）+ 台账 | 流水线会反复重建成品；覆盖会毁掉人工修改 | 人工标记（`todo=`/`preferred=`/`usertag=`）在重建时被继承 |
| **稀疏 checkout** | 便携包不该拖 75 MB `.git` 与几万个链接 | 首次运行只拉 **86 MB**（根目录几个文件 + `scores/`） |

### 检索层（全部在浏览器里）
| 技术 | 为什么 | 收益 |
|---|---|---|
| **八度无关的代价匹配** | 用户哼唱/记谱的八度不可靠 | 召回显著变好，同时八度仍保留用于展示 |
| 段落权重 + 人气代理 | "开头几个音"常落在前奏，权重能纠正 | 与"证据优先"并列裁决配合，减少"排第一但不是那首" |
| **证据优先的并列裁决** | 并列时按随机/字典序是错的 | 代价 → 人工校对(ok) → 置信度 → 版本数(按 `source` 去重) → 段落权/人气/长度 |
| **TypeScript**（2026-10-01 全部迁移完成） | 口径最值钱的地方（token 解析 / 代价匹配 / 并列裁决）与边缘逻辑最怕改错；DOM 代码也想有编译期保证 | `jptok.ts` · `search.ts` · `app.ts` · `worker/index.ts` 四处**都是 TS**；`tsc` 三份配置（前端核心 strict / 主界面过渡 / Worker strict）+ esbuild 只做类型擦除。**零性能回退**（查询中位 139.9 ms vs 151 ms；索引就绪 179–201 ms vs 204 ms）；主界面产物 **46,449 → 33,605 B（-28%）**（顺带剥掉注释，源码里那份'为什么'仍在） |
| 零依赖 ES module | 打开即用、无供应链风险、可审计 | 无框架、无运行时 npm 依赖（devDependencies 只有 wrangler/esbuild/typescript/workers-types） |
| `DecompressionStream` | 31 MB 明文不能直接下发 | 5.12 MB gz 流式解压，204 ms 就绪 |

### 边缘与部署层
| 技术 | 为什么 | 收益 / 坑 |
|---|---|---|
| **Cloudflare Workers + Assets** | 读路径要"零运维 + 全球边缘" | 免费额度内；`_headers` 做内容寻址长缓存 |
| **Worker 用 TypeScript**（2026-10-01） | 边缘代码负责路由/鉴权/注入，出错就是"整站不可用"；类型能挡住一整类错误 | 入口 `worker/index.ts`（`wrangler` 自己 esbuild 打包）；单独 `tsconfig.worker.json`（`@cloudflare/workers-types`，不能和 DOM lib 混） |
| **`/api/health` 探上游（`upstreamOk`）** | 快速隧道会**悄悄死掉**而 secret 仍在 —— 只报 `api:true` 会骗人 | 2026-10-01 实测: 隧道 `Error 1016`，health 却一直 `api:true`，看护几小时没报；现在健康检查真去敲一下上游（3 s 超时） |
| **`assets.run_worker_first`** | `/s/<id>` 靠 SPA 回退，默认**不过 Worker** | 不设它 → 每谱注入**静默失效**（页面照常打开） |
| **每谱注入 meta（Edge SSR-lite）** | 爬虫不跑 JS；1.1 万个谱页否则"同一份 HTML" | `data/og.json` 11,495 条，`/s/<id>` 各有 `<title>`/OG/canonical |
| **Cloudflare Tunnel + 本机写服务** | 写盘/`git commit` 必须在本机；但读要边缘 | 边缘反代 + `X-Token`；`vars` 与 `secret` 同名会报 **code 10053** |
| **FastAPI + Pydantic v2**（2026-10-01 C 阶段） | 写后端要的是**类型化契约 + 自动文档**：投稿 4 种载荷从「字典里摸 key」变成可校验模型，`/docs`（Swagger）由代码生成 | 业务口径**一行没重写**（全部 import 自 `app/server.py`）；4 种 kind 用 discriminated union 表达；错误文案/状态码/CORS 与旧版逐项对齐（见下条） |
| **灰度对拍矩阵** `tools/check_parity_legacy_vs_fastapi.py` | 换传输层最危险的是**边角行为**（预检状态码、404 的 body、越界拒绝、坏 JSON 文案、body 上限、**鉴权与解析的先后**） | 21 条用例 × 三种鉴权场景（无口令/错口令/对口令，后者会真写）**全部一致**；对拍过程当场抓到 4 类差异（含一处**鉴权顺序**差异：新版原本先报 400 解析错、旧版先报 403） |
| **uv**（`pyproject.toml` + `uv.lock`） | 依赖要能**一条命令还原**（换机器、进 CI 都算数） | `uv lock` 解析 30 个包 2.64 s；`uv run python app/api.py 8785` 直接跑起来（实测 `/docs` 200） |
| **Docker + Compose**（一条命令起） | 换机器/进 CI 要能"一条命令复现环境"，而不是靠人记三条命令 | `Dockerfile`（多阶段: uv 依赖层 + 运行层、非 root、`HEALTHCHECK` 用应用自己的 `/api/health`）+ `docker-compose.yml`（`api` + `tunnel` profile；**语料挂卷不烤进镜像**；口令不给默认值，缺了就报错停下）。⚠ 本机**没装 Docker**，所以本机做的是"步骤等价性"验证（干净目录跑依赖层 `uv sync --frozen` → 31 包；再用那套 venv 一字不改跑 Dockerfile 的 HEALTHCHECK），**真正的镜像构建放在 CI 的 `docker` job** |
| **ruff + mypy 渐进门槛** | 新代码要有风格/类型底线，但历史 60+ 脚本全量开会淹没真问题 | `tools/lint_python.py`（唯一真源，pre-commit 与 CI 都调它）: 本次现代化产出的 5 个文件过 ruff、`app/api.py` 过 mypy；`app/server.py` 用 per-file-ignores 登记在案（它是"随时可退回"的备份实现，为风格动它纯风险） |
| **pre-commit** | 让"提交前就该发现的问题"在提交前发现 | 官方文件卫生钩子 + 4 个本地钩子（python 门槛 / `npm run typecheck` / 文档数字对账 / 前端检索用例）；实测 **11 个钩子全过**（tsc 与 search-check 都真跑过） |
| **Prometheus `/metrics`** | "投稿有没有在进来""上游还活着吗"以前只能翻日志 | 官方客户端；`jianpu_http_requests_total{method,path,status}`（**路径用归一化模板**，否则 1.1 万谱页会把时间序列炸掉）+ 耗时直方图 + `jianpu_submissions_total{kind,result}` + 语料规模 gauge。真语料实测 `jianpu_corpus_songs 11495` ✓，用官方解析器校验 **14 个指标族**全部合规 |
| **GitHub Actions 三条流水线** | 本地绿 ≠ CI 绿（D 阶段就被这条打脸，见 STAR 第 10 条） | `checks.yml`: `web`（node 20/22 × 三份 tsconfig + 前端自检 + 性能基线）、`python`（3.11/3.13 × 门槛 + 投稿漏斗 + **起两个实现跑 21 条对拍** + 文档对账）、`docker`（**真构建镜像**并起来打 `/api/health`、`/metrics`） |
| **GitHub Pages 只读镜像 + Actions** | 多一个入口 + 备份 + 老链接不断 | `canonical` 指正式域名，避免被判重复内容 |

## 三、刻意没用的（面试问"为什么不用 X"时这么答）

| 没用 | 理由 | 什么时候会引入 |
|---|---|---|
| 数据库（Postgres/SQLite） | 语料是"文件 + 一行一首"，检索在浏览器里；引入 DB 只增加部署与备份面 | 需要并发写入、权限、或服务端检索时（阶段 E 之后） |
| 前端框架（React/Vue） | 单页 + 列表渲染，原生 DOM 足够；框架会带来构建链与体积 | 交互复杂度上来时（现在是 ~1 千行 TS） |
| 前端打包器（把模块打进一个 bundle） | 零打包 = 无供应链、产物可直接 diff；浏览器原生 ESM 完全够 | 只在需要"一次请求 + 极致体积"时；现在只引入 `esbuild` 做**类型擦除**（仍然逐个模块发布） |
| Docker | 本机就是唯一写节点，`setup.cmd/run.cmd` 两条命令够用 | **阶段 D**（换机器/CI 复现时收益最大） |
| 向量检索 / Embedding | 现有"代价匹配"可解释、可评测、在浏览器里够快 | **阶段 E**：语义/哼唱相似度作为**补充**召回，而不是替换 |

## 四、六个能扛追问的难题（STAR，全部有实测与复盘）

### 1. 多页谱只转了第一页（残谱）
* **S/T**：榜单曲《爱错》在库里只有 6 个音符 → 实际是 2 页谱。
* **A**：加多页拼接：每页单独过纯度门（挡掉"双谱目录"里的五线谱页），按页拼接；页数上限 4 防钢琴谱。
* **R**：对 858 个多页目录回锅，761 份新稿、**487 份变长**（中位 +276 音、累计 +184,274 音）。

### 2. 我自己的"织体判据"把 13 份真歌截断（**最有料的一段**）
* **S**：为挡钢琴织体，我先写了"逐页丢 >300 音"。上线后抽查发现《旅行》1580→357、《圣诞结》416→112。
* **A**：从 sidecar 的 `page_notes`/`dropped_pages` 定位是判据在丢页；把"逐页判"改成"**整份按每页中位**判"（中位 >400 音才整份跳过；单页 >600 音才丢，只兜极端）；用 15 个真实样本离线验证（13 留 / 2 跳，**零截断**）；再写 `qa_shorter_after_redo.py` 把"变短"自动分成"真丢页 vs 旧稿虚高"。
* **R**：13 份真歌进入补转名单（用新口径重跑）；后续 858 个目录的回锅里，"真丢页"只剩已知的那 5 份。

### 3. 置信度做成"零成本"并且可信
* **S**：想知道"哪个数字模型没把握"，但不接受为了它把转写速度砍半。
* **A**：贪心解码 + `output_scores=True` 取每个数字的 top-1 概率；多页按每页数字数**加权平均**，`conf_p10` 取**最差那一页**的分位。
* **R**：开关前后耗时无差异（30.1/30.0 s vs 30.0/30.4 s）；自查时发现"多页只取到最后一页"的 bug 并修掉。

### 4. 边缘 SEO：SPA 遇上"爬虫不跑 JS"
* **S**：1.1 万个 `/s/<id>` 在爬虫眼里是同一份 HTML（同一个 `<title>`）。
* **A**：构建期产出 `data/og.json`（id→曲名/歌手/音符数）；Worker 对 `/s/<id>` 注入这一首的 meta；
  **必须** `run_worker_first=true`，否则请求在资源层被接走、Worker 根本不跑。
* **R**：`/s/<id>` 的 `<title>` 变成"曲名 · 简谱"，canonical/OG 同步；排障经历：`let OG_CACHE` 被一次编辑误删 →
  ESM 严格模式 ReferenceError → 被 `try/catch` 吞掉 → **页面正常、功能静默失效**；此后在 `/api/health`
  暴露 `og`（索引条数）当"指示灯"。

### 5. 写回架构：只读镜像 vs 边缘写
* **S**：投稿/补标签要写盘 + `git commit`，而站点是静态托管的。
* **A**：Worker 只反代并注入 `X-Token`；真正写在本机（隧道出去）；读路径完全不依赖本机。
* **R**：域名上点 ＋ 真写进语料并 commit（实测：`{"ok":true,"committed":true,"refresh":true}`）；
  踩坑：`API_UPSTREAM` 同时写在 `vars` 与 `secret` → `Binding name already in use [code 10053]`。

### 6. 数据一致性：两种"只动一半"的坑
* **S**：① 导入是"只拷不覆盖"（保护人工修改）→ 成品里新填的元数据**进不了语料**（实测 2,153 处空栏）；
  ② 语料"只增不删" → 流水线早已判废/换名的稿子留在库里（实测 1,332 份）。
* **A**：① 写 `merge_metadata_into_corpus.py`：**只填语料里为空的栏**、绝不覆盖人工值、只碰元数据行；
  ② 写 `prune_rejected_from_corpus.py`：默认 dry-run，并**先分一刀**——"清了这首就一个版本都不剩"的 222 份默认不动。
* **R**：标签覆盖 60.6% → **79.5%**；清理项都有名单、影响面与"移而不删"的落点。

### 7. 前端 TypeScript 化：零性能代价，但**顺手抓到三个"从来没跑过"的东西**
* **S/T**：把 5 千行前端（token 解析 / 代价匹配 / 卡片渲染）迁到 TypeScript，要求**行为不变、性能不变**，且线上全程可用。
* **A**：
  1. 只做"渐进迁移"：源文件优先取 `.ts`，没有就退回 `.js` —— 中间态照样构建、照样上线（`build_dist.mjs` 的 `sourceOf()`）；
  2. 构建用 esbuild **只做类型擦除**（不打包、不加运行时依赖），`tsc --noEmit` 单独做类型检查并进 CI；
  3. 检查脚本改走 `tools/_built.mjs`（按需转译 + 依赖先行），保证"测的就是线上那份逻辑"。
* **R**：
  * 性能：索引就绪 **204 → 201 ms**，查询中位 **151 → 138.7 ms**（无回退）；
  * **抓到三个静默问题**：① `buildIndex` 的字段白名单漏了 `conf`/`confP10` → "按转写置信度优先"这条并列依据一直拿到 0.5（等于没生效）、卡片上也永远不显示置信度（本项目**第 5 次**栽在"白名单式字段复制"上，现在有回归断言盯着）；② `app.renderScore` 从来没有 `export`，而 `check_page.mjs` 里写的是 `app.renderScore(...)` → 那条自检**从写下那天起就没通过过**；③ `check_tune.mjs` 断言字面量 `<th>歌手</th>`，而 schema 化之后表头是 `<th><span title=…>歌手</span></th>` → **永远不可能通过**；
  * 构建脚本自己也有一个：拼 `.ts` 时忘了去扩展名（找 `jptok.js.ts`）→ 静默少两个产物文件。已改成"缺文件即构建失败"。
  * **主界面 867 行走的是渐进迁移**（`tsconfig.app.json` 过渡配置：数据层真类型、DOM 胶水层待收紧），并在**文件头写明**下一步要修的三类 —— 业界叫 strangler 迁移：不为了'看起来全 strict'而把回归风险堆在一次改动里。过程中把 6 处事件委托收成一个带泛型的 `closestFrom<T>()`，**代码反而更短**。

### 8. 隧道悄悄死了，而监控说"一切正常"（可观测性那一课）

* **S**：线上投稿忽然全挂 —— Cloudflare 回 `Error 1016 Origin DNS error`（快速隧道域名解析不到）。
* **A**：先重建隧道恢复服务；再改**判据**：`/api/health` 增加真去敲上游的 `upstreamOk`（3 s 超时），
  看护脚本从"看 `api`（＝secret 配了没）"改成"看 `api && upstreamOk`"。
* **R**：一条 `curl https://jianpu-db.org/api/health` 现在能区分"没配"和"配了但对方死了"；
  **教训：监控不能只查配置在不在，要查上游活不活。** 同一天我加的"GPU 让路闸"也自锁过一次
  （计划任务的子进程查到"自己在 Running"于是永远等），同样用"上限兜底 + 环境标记"修掉 —— 两件事一个道理：
  **任何"等待/健康判断"都必须有退路。**

### 9. 换掉传输层：靠「对拍矩阵」而不是「跑一遍自检」来证明行为一致

* **S**：写后端要从 Python 标准库搬到 FastAPI（为了类型化契约与自动文档），但投稿是**唯一会写盘 + git commit** 的路径 —— 换错了就是脏数据/丢投稿。
* **A**：业务口径**不重写**（复用 `server.py` 的函数），只换传输层；然后用 **21 条请求 × 三种鉴权场景**逐项比对（状态码 / CORS 头 / 归一化后的响应体），并且**对拍只打隔离实例**（临时语料库 + 独立 git 仓库，不碰真数据）。
* **R**：对拍当场抓到 4 类差异，全都不是「跑一遍自检」能发现的：① `OPTIONS` 预检 204 vs 405；② 静态/原图/404 少一个 CORS 头（浏览器会读不到响应体）；③ **鉴权顺序**：新版先报 400 解析错、旧版先报 403 —— 安全语义上的实打实差异；④ 中间件早退的响应漏了 CORS。修完全部 **21/21 一致**才切换；切换后立刻在正式域名上跑了一次真投稿（留档 + `git commit` 成功）。

### 10. "本地一直绿，CI 一直红"——三次都栽在**测试装置**上

D 阶段把质量门搬到 CI 之后，连着暴露了三个问题，**没有一个是业务代码的 bug**，全是"装置/环境"的：

* **① 少一行 `npm ci`（我的回归）**：B 阶段给 Pages 工作流加了 `npm run typecheck`、又让构建依赖 `esbuild`，
  但那个工作流**从来没装过依赖**（以前只用 Node 内置模块）。于是 push 之后 `Deploy to GitHub Pages` 直接红。
  排查顺序值得记：先比"本地构建哈希 vs 仓库根 vs 镜像 vs 正式站"（**全一致**，排除掉最像的原因）→
  再把 `node_modules` 挪走、在本机复现出 `'tsc' is not recognized`（**证实**）→ 加 `npm ci` + npm 缓存。
* **② 对拍脚本自己也要对环境做归一化**：CI 里两边各自用一份隔离语料库（路径不同），而错误文案里带着这个路径
  （"找不到 linkurl.py —— JIANPU_DB=…"），于是**4 条全部误报**。修法: 从两边 `/api/health` 读回各自的 `repo`，
  在比对前把路径替换成 `<DB>`（和之前处理 origin/端口是同一个套路）。
* **③ 隔离库没有基线提交**：`git` 不跟踪空目录，CI 里挑不到真曲谱时 `git commit` 以 "nothing to commit" 失败
  → **"写回提交"那条路径根本没被测到**。修法: 生成器固定写一个说明文件把基线立起来。

**结论（面试可讲）**：把"本地能跑"升级成"CI 能证明"时，先怀疑装置、再怀疑代码；
而"对拍/回归"这类装置**自己也会骗人** —— 误报会让人放松对真差异的敏感度，所以装置的信号必须做环境归一化。
## 五、常见追问与答法（面试 Q&A）

1. **为什么不用数据库？** 语料是文件 + JSONL，检索在浏览器；DB 会引入部署/备份/权限三件套，收益为零。需要并发写或服务端检索时再上。
2. **前端不上框架怎么维护？** 单页 + 列表渲染，原生 DOM 足够；关键是**口径只有一份**（token 解析 Python/JS 互锁）与**自检**（17 个站点检查脚本）。
3. **OCR 质量怎么保证？** 三道：纯度门（挡错类型）、织体判据（挡非旋律）、置信度（提示可疑）+ 人工 `status=ok` 与并列提示。
4. **八度为什么不用？** 哼唱/记谱的八度不可靠；参与检索只会掉召回。八度仍保留用于展示与"同一旋律不同八度"的说明。
5. **同名多版本怎么排？** 归一化分组键归组；并列时按证据优先，且"版本数"**按 `source` 去重**（否则一页多稿会灌水）。
6. **怎么回滚/审计？** 一切进 git；清理动作"只移不删"（`scores-parked-*/`），台账记录"哪个 batch 转成了哪个成品"。
7. **为什么写路径不落边缘？** 写要动本地仓库并 commit，且本机是唯一可信节点；边缘只做反代 + 鉴权注入，读性能不受影响。
8. **密钥怎么管？** `wrangler secret put`；本机用环境变量（`JPSUBMIT_TOKEN`）。**别**把同名变量同时放 `vars`（会 10053）。
9. **怎么监控"线上是不是好的"？** `/api/health` 暴露 `api`/`upstream`/`og` 三个字段；另有两个看护：隧道 15 分钟、QA 60 分钟；并与本地语料对账 `stats.json` 的曲数。
10. **幂等性怎么保证？** 导入只拷不覆盖；转写按 dir 输出可重跑；`--rescue` 专门处理"内容变了要重新导入"。
11. **性能瓶颈在哪、怎么扩？** 见 `ARCHITECTURE.md` 第五节：转写受单卡限制（59–95 份/小时）、浏览器查询 151 ms（可上倒排剪枝或 Rust→Wasm）。
12. **数据来源与合规？** 只保存**原站页面地址与元数据** + 自己转写的数字序列；原图不外链、不打包。
13. **成本？** Cloudflare 免费额度内（Workers 10 万请求/天、Pages、R2 免费 10 GB）；GPU 是本机 4070。
14. **评测怎么避免自欺？** 固定金曲清单、L=11/L=15 两档、Top-1/3/5、**错音必须为 0** 才算一次有效查询，并公开"代价并列率"（并列里排第一不算唯一命中）。
15. **如果索引大 10 倍？** 拆冷热索引 → 首屏只下热门；查询侧先 n-gram 剪枝；或把匹配放服务端（同口径）。
16. **怎么保证两个实现不漂？** 互锁测试：`check_jptok_parity`（Python↔期望值）、`check_jptok_js`（JS↔期望值），21,711 token 逐项一致。
17. **为什么注释里全是"为什么"？** 500+ 处决策注释（含踩坑日期与实测数字），把"当时怎么想的"留在代码里 —— 这是这个项目最值钱的部分之一。
18. **多语言/移动端？** 前端有 zh/en 词表；布局是响应式单栏（卡片/谱页两态）。
19. **如果别人要接手？** 三个仓库 + 一份 `ROOT_README`/`醒来汇报` + 每步都有自检；便携包 `jianpu-server` 让"换台电脑跑起来"只要 Python。
20. **你觉得这套最脆弱的一环？** 写路径依赖本机在线与隧道（读路径不受影响）；其次是单卡转写吞吐。两者都有明确的替代路线（上云存储/队列、批处理并行）。
